# 滚塑仿真技术方案

## 1. 目标与范围

本项目是基于 WebGPU 的滚塑颗粒流动仿真。模具网格经过体素化后，颗粒不再以单个可见小球或刚性颗粒渲染，而是以“占据质量场”表示。GPU 负责每个时间步的重力、旋转惯性、休止角坍塌和质量迁移，渲染阶段只提取颗粒堆的外部包络面，形成类似液面的连续视觉效果。

当前方案重点解决以下问题：

- 模具姿态变化时，颗粒应沿有效重力方向向低处流动。
- 表面坡度超过休止角时，应出现明显的雪崩式坍塌，而不是长期保持初始平面。
- 局部流动不能产生大量穿模或颗粒凭空消失。
- 仿真过程可实时显示，也可以隐藏中间帧并快速计算最终状态。
- 壁厚计算应避开仿真开始阶段的初始堆积瞬态。

本实现是面向交互的体素质量场模型，不是带真实接触约束的离散元法（DEM）。因此它强调 GPU 并行、视觉连续性和可调参数，而不是对单颗粒碰撞进行工程级精确求解。

## 2. 系统架构

```text
STEP/STP 模具网格
        |
        v
CPU 体素化与腔体判定
        |
        +--> cavityMask / cavityPositions / cavityGridIndices
        |
        v
GPU 颗粒质量场
  massIn <-> massOut      (双缓冲)
        |
        +--> 26 邻域流动、重力、离心力、休止角、容量限制
        |
        v
GPU 表面包络着色
  表面体素 + 质量梯度 + 局部面片
        |
        v
屏幕显示 / OBJ 表面导出 / 壁厚计算
```

主要模块：

| 模块 | 职责 |
| --- | --- |
| `src/simulation.js` | 模拟时钟、旋转姿态、体素化、初始填充和参数管理 |
| `src/renderer.js` | WebGPU 资源、颗粒计算 shader、表面渲染 shader、readback |
| `src/main.js` | UI 参数、动画循环、实时/快速模式、壁厚时序和统计信息 |
| `index.html` / `styles.css` | 仿真控制面板和状态显示 |

## 3. 颗粒数据表示

### 3.1 规则体素网格

当前颗粒场使用 `100 x 100 x 100` 的规则网格，计算域边长为 `1.8`，因此单元边长为 `0.0180`。每个网格单元保存一个归一化质量值：

```text
mass[i] = 0       空单元
mass[i] = 1       达到单元容量
0 < mass[i] < 1   部分填充
```

模具内部通过 CPU 体素化生成 `cavityMask`。只有腔体内的单元参与颗粒计算，外部单元不会接收颗粒质量。这样可以避免颗粒场在模具外部无限扩散，但边界精度仍受体素尺寸影响。

### 3.2 颗粒总量

初始填充量由腔体体素数量与填充体积比决定。系统保存：

- `granuleInitialMass`：仿真重置时的总质量。
- `granuleTargetMass`：当前应保持的总质量。
- `massIn` / `massOut`：GPU 双缓冲质量场。

双缓冲避免同一个迭代中前面的工作组已经写入的数据影响后面的读取。每次 GPU 松弛迭代完成后交换两个 storage buffer。

## 4. 旋转与有效重力

### 4.1 时间推进

当前每个物理批次使用固定的物理时间步，并拆分为 30 个子步：

```text
physicsStepSeconds = 1 / 60
substepDt = physicsStepSeconds / subSteps
subSteps = 30
```

固定步长保证“显示过程”和“不显示过程”执行完全相同的物理步序列，最终颗粒状态不会因渲染频率不同而改变。正常显示模式每个动画帧执行 1 个物理批次；隐藏显示模式每个动画帧执行 30 个相同批次，只跳过中间画面，因此不会把同一个墙钟时间重复应用到物理计算中。仿真没有人为设置的结束时长，持续运行到剩余颗粒质量为零、颗粒全部沉积后自动停止。

界面同时显示两种时间：`仿真时间`是滚塑过程的物理时间，`仿真用时`是从点击开始到完成的真实墙钟时间。快速模式下前者会明显大于后者，这是计算加速的预期结果。

### 4.2 姿态和重力方向

主轴转速和副轴转速分别累加到 `rotationAngle`、`rotationAngle2`。副轴角度 `ax` 将局部竖直方向变换为：

```text
upLocal = [0, cos(ax), -sin(ax)]
gravityDown = -upLocal
```

因此颗粒的“下方”不是固定世界坐标，而是随模具姿态变化。GPU 每个计算迭代都使用当前的重力方向，避免只在初始化时计算一次倾斜平面。

### 4.3 离心力

局部角速度向量由两个转轴组合得到：

```text
omega = [rotationSpeed2,
         cos(ax) * rotationSpeed,
         -sin(ax) * rotationSpeed]
```

对体素中心位置 `r`，shader 计算旋转造成的离心项：

```text
centrifugal = -cross(omega, cross(omega, r)) / 9.81
effectiveDown = normalize(gravityDown + centrifugal)
```

该项只改变局部流动趋势，不会凭空增加颗粒质量。对于低转速和小半径，重力仍然占主导；只有离心项足够大时，颗粒才会贴壁并改变沉积方向。

## 5. GPU 颗粒流动算法

### 5.1 邻域与流动方向

每个活动体素由一个 WebGPU compute invocation 处理，检查周围 26 个邻居（面、棱、角邻接）。对邻居方向 `d`，先计算从当前体素指向邻居的单位向量，并投影到有效重力方向：

```text
descent = dot(normalize(d), effectiveDown)
```

`descent` 越大，表示该邻居越接近有效重力的下游方向。只有向下或接近向下的邻居才会产生明显质量通量；向上迁移不会被允许。

### 5.2 休止角阈值

UI 中的休止角 `theta` 转换为：

```text
sinRepose = sin(theta)
```

离散体素坡面达到该阈值后才进入主坍塌通道。坡度驱动采用非线性指数，使超过休止角的区域快速流动：

```text
excess = clamp((descent - sinRepose) / (1 - sinRepose), 0, 1)
avalancheDrive = pow(excess, 0.62)
```

当整体姿态的重力倾斜已经超过休止角时，再施加全局坍塌增益：

```text
globalTilt = length(gravityDown.xz)
globalAvalanche = 1 + 5 * clamp(
    (globalTilt - sinRepose) / (1 - sinRepose), 0, 1)
```

这两个因素共同解决“大角度但流动很慢”的问题：局部坡面提供触发条件，全局倾斜提供启动增益。

### 5.3 亚临界蠕动

低于休止角但仍存在下坡分量时，使用较小的蠕动通道：

```text
subcriticalDrive = descent * 0.48
```

蠕动用于消除体素台阶和初始填充造成的局部尖峰，使表面逐步趋于稳定；它的强度低于雪崩通道，避免所有坡面都变成过度流动的液体。

### 5.4 通量、容量和质量守恒

一个迭代中，每个体素分别累计：

- `outgoing`：当前体素希望流出的质量。
- `incoming`：邻居希望流入当前体素的质量。

然后进行两级限制：

```text
limitedOutgoing = min(outgoing, currentMass)
availableIncoming = max(0, 1 - currentMass + limitedOutgoing)
limitedIncoming = min(incoming, availableIncoming)
nextMass = currentMass - limitedOutgoing + limitedIncoming
```

这样可以保证：

- 空体素不能流出质量。
- 单元质量不会小于 0 或超过容量 1。
- 计算迭代本身不会因局部通量超过容量而产生爆炸。

每个物理批次调用 `stepGranules(params, iterations = 16)`，连续执行 16 次松弛，让质量在同一时间步内传播得更远。这里的“GPU 松弛次数”不是提高转速，也不是改变物理时间，而是增加每个时间步内的离散流动迭代数。当前值 16 是在 100^3 体素规模下对流动收敛速度、表面稳定性和 GPU 开销的折中；次数越高，坍塌响应通常越快，但 GPU 开销也按比例增加。

### 5.5 数值漂移校正

由于通量在离散邻域中是近似对称计算，长时间运行仍可能出现浮点误差或边界截断造成的总量偏差。当前每 4 帧执行一次 GPU readback：

1. 对有效颗粒体素求和得到实际总质量。
2. 与 `granuleTargetMass` 比较。
3. 偏差超过 1% 时，对质量场做统一比例校正。
4. 将校正后的数据写回 `massIn` 和 `massOut`。

该机制用于修正数值漂移，不是“生成”或“删除”颗粒。若出现瞬间坍塌后颗粒体积明显减少，优先检查 readback、腔体边界和渲染等值面，而不是简单提高体素数量。

## 6. 表面包络渲染

### 6.1 不显示单个体素

当前不再把每个颗粒体素渲染成独立立方块。渲染 shader 对每个体素检查 6 个面：只要邻居为空、越过腔体边界或低于等值面，就认为该体素拥有外露表面。

每个表面体素实例生成一个局部面片，而不是 6 个完整立方体面。面片中心沿质量梯度和边界方向调整，面片之间使用适度重叠形成连续包络，视觉上更接近一滩水或连续颗粒料面。

### 6.2 法线与曲面效果

表面法线优先使用相邻质量差分得到的梯度；梯度过小时使用腔体边界方向作为后备法线。法线再用于切线、双切线和面片朝向计算，从而避免所有表面片都固定朝向世界坐标。

当前显示阈值约为 `isoLevel = 0.12`。降低阈值会显示更薄的残余质量，提高阈值会使表面更干净但可能隐藏薄层。

## 7. 壁厚计算时序

仿真启动后的前 5 秒（物理仿真时间）只推进颗粒，不开始累计壁厚：

```text
wallThicknessDelaySeconds = 5
```

当 `simTime >= 5` 后，才根据当前颗粒质量场在模具表面采样并计算沉积厚度。这样可以避免初始填充尚未展开时，局部堆积被误认为最终壁厚。该延迟使用仿真时间而不是浏览器墙钟时间，因此快速模式下仍保持相同的物理含义。

## 8. 实时显示与快速仿真

控制面板中的“显示过程”复选框只控制显示频率和批处理数量，不改变转速、重力、休止角或固定 `dt`：

| 模式 | 每次动画循环的物理批次 | 屏幕更新 |
| --- | ---: | --- |
| 显示过程 | 1 | 每批次渲染 |
| 不显示过程 | 30 | 只在暂停、完成或最终状态渲染 |

关闭显示过程后，仿真仍按相同的仿真时间步执行，只是一次处理更多物理批次，避免把时间耗费在中间帧绘制上。该模式提高计算吞吐量，但不改变单个物理步中的转速、重力或流动参数。

## 9. 当前主要参数

| 参数 | 当前值/范围 | 作用 |
| --- | --- | --- |
| 体素分辨率 | `100³` | 流动空间离散精度和 GPU 开销 |
| 计算域边长 | `1.8` | 体素坐标映射范围 |
| 时间推进 | `1/60 s` 物理批次 | 每个物理子步为批次时间除以 `30` |
| 每步松弛次数 | `16` | 单个物理批次内的质量传播次数 |
| 流动系数 | `1.6` | 通量基础增益 |
| 雪崩指数 | `0.62` | 超过休止角后的非线性响应 |
| 亚临界蠕动系数 | `0.48` | 低于休止角时的缓慢流动 |
| 全局坍塌增益 | `1 ~ 6` | 整体倾斜超过休止角时的启动增强 |
| 壁厚延迟 | `5 s` | 忽略初始堆积瞬态 |
| 仿真终止条件 | 无固定时长 | 剩余颗粒为零、全部沉积后自动结束 |

## 10. 已知限制与后续方向

1. 当前是规则体素质量场，不是 DEM。没有逐颗粒速度、碰撞、静摩擦和滚动摩擦状态，因此无法复现颗粒碰撞链的全部细节。
2. 26 邻域通量是启发式模型，局部质量守恒通过流出/流入限制和周期 readback 校正保证；它不是严格的有限体积守恒求解器。
3. 模具曲面仍以体素腔体边界表达。体素过大时会有穿模或台阶，继续提高分辨率会增加显存和计算量，不能单独解决算法层面的流动响应问题。
4. 当前可优先增加曲面附近的自适应细分：在边界使用更小体素或八叉树，在内部使用较大体素，以控制穿模和性能。
5. 可将全局坍塌增益改为与坡度、局部堆积厚度和时间相关的连续函数，减少启发式参数对不同模具尺寸的依赖。
6. 可增加 GPU reduction 和局部守恒诊断，减少 readback 频率；同时保留质量误差曲线，便于判断“渲染变薄”与“质量真的减少”的区别。
7. 若需要更强物理真实性，应引入速度场、压力/不可压缩约束或粒子-网格（PIC/FLIP）模型；这会显著增加实现复杂度和 GPU 带宽需求。

## 11. 结论

当前方案用“体素质量场 + GPU 26 邻域松弛 + 休止角雪崩驱动 + 重力/离心有效方向 + 表面包络渲染”实现滚塑颗粒料面的快速近似。流动核心在于有效重力方向和超过休止角后的非线性通量；显示核心在于只渲染外露包络面；稳定性核心在于双缓冲、容量限制和总质量校正。该结构适合继续沿自适应体素、严格守恒通量和速度场方向优化。
